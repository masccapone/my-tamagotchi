# 소규모 기업 경영정보 질문 서비스 요약 (교차검증용)

이 문서는 다른 AI나 전문가에게 설계를 검토받기 위한 요약입니다. 실제 회사명, 거래처명, 금액은 넣지 않았습니다.

## 1. 해결하려는 문제

- 소규모 제조·처리업 회사에서 ERP(더존 WEHAGO)를 쓰지만, 대표는 ERP를 쓸 줄 모르고 직원(경리)은 전표 입력 위주로만 쓴다.
- 그래서 대표가 원하는 숫자를 바로 보기 어렵다.
- 대표가 자주 묻는 질문 11개:
  1. 이 업체에 이번 달 얼마, 언제 줘야 하나
  2. 이 업체 돈이 들어왔나
  3. 이번 달 나갈 돈과 들어올 돈
  4. 이 비용은 무엇인가
  5. 이 비용이 이번 달 왜 많이 나갔나
  6. 이번 달 이익(손실)
  7. 줄일 수 있는 비용 항목
  8. 이익으로 전환하려면 매출이 얼마나 더 필요한가(BEP)와 비용 절감 방법
  9. 현재 통장 잔액
  10. 이 업체 단가와 실제 청구 일치 여부
  11. 이 업체 이번 달 물량

## 2. 서비스 컨셉

- 대시보드를 탐색하는 도구가 아니라, 질문하면 한 줄 답과 근거 표를 주는 도구.
- ERP를 교체하지 않고, ERP에서 내려받은 엑셀을 올려서 분석한다.
- 경리가 파일을 올리고, 대표는 결과만 본다.
- 최종 형태: 회사 PC에 설치한 로컬 서버가 파일을 저장하고, 대표가 카카오톡 채널 챗봇으로 질문하면 답한다.

## 3. 입력 자료

| 자료 | 설명 |
|---|---|
| 분개장 | ERP에서 내려받은 전표 전체(전표일자, 전표번호, 구분, 계정코드, 계정과목, 차변, 대변, 거래처, 적요). 여러 해를 합쳐 올림 |
| 거래내역 | 건별 수량·단가·금액(방향, 거래처, 품목, 단가종류). 현장 장부(반입/반출 현황)를 자동 변환하거나 템플릿 사용 |
| 업체마스터(선택) | 같은 업체의 다른 표기(별칭), 결제기한 |

설계 근거: 소규모 회사는 계약서 이후 단가가 자주 바뀌어서 계약서보다 실제 거래 단가 기록을 입력으로 삼는다. 월별 손익계산서와 제조원가명세서는 분개장에서 재구성할 수 있어 따로 받지 않는다.

## 4. 핵심 계산 로직과 가정

1. **계정 분류:** 더존 계정코드 체계 기준(4xx 매출, 5~7xx 제조원가, 8xx 판관비, 9xx 영업외). 코드가 없으면 계정명으로 추정.
2. **월별 손익 두 가지:**
   - 손익계산서 기준: ERP 결산 전표 반영
   - 발생비용 기준: 결산 전표 중 제조원가 계정의 대변(재공품 대체)을 제외하고 월별 실제 발생비용으로 재구성
   - 이유: 이 회사는 제조원가를 분기 말에 한꺼번에 매출원가로 대체해서, 분기 중간 달의 손익계산서 손익이 왜곡된다.
3. **결산 예상 조정:** 감가상각, 퇴직급여, 충당부채전입, 주식보상, 이자 정산처럼 분기 말에만 입력되는 비용이 아직 없는 분기를, 직전 결산 분기(최대 2개) 평균으로 추정해 더한다. 진행 중인 분기는 경과 일수만큼만 반영. 실제 결산 전표가 들어오면 자동으로 실제 값으로 대체. 화면에서 끌 수 있음.
4. **채권/채무:** 거래처별 FIFO로 청구분과 수금·지급을 매칭해 미결 잔액과 연령(30/60/90/180일)을 계산. 마이너스 잔액 업체(이전 연도 기초 잔액 누락)는 경고 후 제외.
5. **결제 예정일:** 계약서가 아니라 업체마스터의 결제기한, 없으면 그 업체의 과거 평균 결제일(FIFO로 계산)로 추정. "실제 지급 결정이 아니라 추정"임을 항상 표시.
6. **BEP:** 매출과 변동비는 거래내역 기준(반출 처리·운반비를 변동비로 봄), 고정비는 분개장 발생비용에서 변동비를 뺀 값. 결산성 비용은 분기 평균 월할. 공헌이익률 5% 미만이면 계산 불가로 표시.
7. **데이터 점검(자동 경고):** 거래내역과 분개장의 누적 매출 차이, 차변·대변이 안 맞는 전표, 기초 잔액 누락 의심 업체, 원가 미결산 달, 마감 미완료 달.
8. **통장 잔액:** 분개장에 기초 잔액이 없어서 사용자가 기준일 잔액을 한 번 입력하면 그 이후 증감을 반영.

원칙: 모든 숫자는 코드가 계산하고, 질문 해석(자연어)은 계산과 분리한다. 나중에 AI를 붙여도 AI는 질문 의도·업체·월만 뽑고 숫자를 직접 만들지 않는다.

## 5. 현재 구현 상태

- 정적 웹앱(브라우저 안에서 엑셀 파싱·계산, 서버 없음). 질문 버튼 11개로 답변.
- 자연어 질문 해석기(규칙 기반): 질문 종류·업체·월·비용 항목 추출. 자체 테스트 25문장 통과(작성자가 만든 문장이라 낙관적일 수 있음).
- 1단계 진행 중: 회사 PC 로컬 서버(경리 업로드·저장, 대표 조회, 비밀번호 로그인).

## 6. 목표 아키텍처

```
경리 PC ─(사내 웹, 엑셀 업로드)→ 회사 로컬 서버(항상 켜진 Windows PC)
                                  │ 원본 파일 + 분석용 JSON 저장, 분석 엔진
                  대표 ← 사내 웹 / 카카오톡 채널 챗봇(질문→답)
                                  ▲
        클라우드 중계 서버 ←(회사 PC가 먼저 접속, 방화벽 개방 없음)← 카카오톡 요청
```

- 카카오톡 채널 챗봇(카카오 i 오픈빌더): 스킬 서버는 공인 IP/도메인 필요, 응답 5초 제한(콜백 가능), 비즈니스 신청 필요. 그래서 중계 서버 방식.
- 질문 문장만 외부로 나가고 재무 숫자는 회사 서버에서 만든 답변으로만 돌려주는 설계를 목표.
- 설치는 회사 직원이, 유지보수는 개발자가 담당. 자동 시작, 원격 업데이트, 로그, 백업 필요.

## 7. 알려진 한계

- 더존 계정코드와 결산 방식에 맞춘 구현. 다른 ERP는 어댑터 보완 필요.
- 결산 예상 조정은 직전 분기 평균 기반 추정이라 신규 설비 등 변동에는 오차가 있음.
- 반입/반출 현황 변환은 근사(운송업체 정보 부재, 청구처 정보 부재).
- 결제 예정일은 이력 기반 추정.
- 한 회사 데이터로만 검증함(범용성 미검증).
- 대화형 AI는 아직 없음(규칙 기반 해석만).

## 8. 검토를 요청하는 질문

1. 질문-계산-답변을 분리하고 AI는 의도 해석만 맡기는 구조가 소규모 기업 재무 질의응답에 적절한가? 놓친 위험이 있는가?
2. 분개장을 공통 입력 표준으로 삼는 것이 다른 ERP·다른 업종으로 범용화할 때 현실적인가?
3. 결산 예상 조정(직전 분기 평균)의 방법론에 회계적으로 문제가 있는가? 더 나은 추정 방법은?
4. 카카오톡 + 중계 서버 + 로컬 서버 구조의 보안·법적 위험(재무정보 처리 위탁, 개인정보, 신용정보)은 무엇인가?
5. 비전문가가 설치·유지보수하기에 로컬 서버 방식이 적절한가? 클라우드 방식과 비교하면?
6. 이 서비스를 여러 회사에 판매할 때 사업적으로 빠진 부분(가격, 책임, 지원)은?
7. 질문 11개 외에 대표가 반드시 묻는데 빠진 질문이 있는가?
